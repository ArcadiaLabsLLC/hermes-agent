## Part A — `FORK-PATCH-IN-TEARDOWN`

### A.0 The class, and what the chain does today

`monkeypatch` is ONE `MonkeyPatch` per test, shared by every fixture and the body. pytest undoes it
at the `monkeypatch` fixture's own teardown, which is AFTER every fixture that depends on it has
torn down — so a patch the body pushed (a raising resolver, a stubbed home, a counted `rmtree`) is
live through every fixture teardown. The two instances fixed in `82e028ecdc` were exactly that; the
detector today is the teardown ERROR the gate reports after the fact.

The chain already does the right split for ONE population: `pytest_pyfunc_call` narrows
`monkeypatch.undo()` to the body's tail (entries above the post-setup stack length) for tests
carrying `SCOPED_MONKEYPATCH_UNDO_MARK`. The row's trap is why that split cannot be applied blind
at call end: a fixture the body requests late (`request.getfixturevalue`) sets up DURING the call
phase, pushes its entries above the base, and its post-yield code still expects them at its
teardown. Dropping them at call end moves the defect from the fixture that read a body patch to the
late fixture that lost its own. Thirteen body sites in `tests/` call `getfixturevalue` today
(`grep -rn getfixturevalue tests --include=*.py`, conftests excluded); the chain itself does it in
`_claude_home_is_tmp_path` (during setup, so below base — unaffected).

### A.1 Per-entry provenance: by RANGE, taken at the fixture-setup hook

Not a tag on the entry (entries are pytest's private tuples; tagging means wrapping
`setattr`/`setitem`/`chdir`/`syspath_prepend` on the instance before any fixture runs) and not a
re-read of the body's source (a walker sees only spellings). Provenance is the stack INDEX RANGE a
fixture's setup pushed, recorded by a `pytest_fixture_setup` hookwrapper while the item is in its
call phase:

- `pytest_pyfunc_call` (hookwrapper, the existing one, moved) takes the base once every fixture has
  set up: `base = (len(mp._setattr), len(mp._setitem), mp._cwd is None, mp._savesyspath is None)`
  and marks the item in-call (`item._hermes_call = CallRecord(base)`).
- `pytest_fixture_setup(fixturedef, request)` (hookwrapper): when `request.node` carries a live
  `_hermes_call`, note `len(_setattr)`/`len(_setitem)` before and after the yield and whether
  `_cwd`/`_savesyspath` went from `None` to set inside; append the two index ranges and the two
  flags to `CallRecord.late`. A cached fixture does not re-enter setup, so it adds no range (it
  pushed nothing). Nested late requests nest their ranges; the union is what matters. A module- or
  session-scoped fixture cannot use the function `monkeypatch` (ScopeMismatch), so it is never on
  this stack.
- Everything above base and outside every late range is the body's. That is the definition; the
  hook never reads a frame or a source line.

### A.2 The exact hook change

New module `tests/_downstream/body_patch_scope.py` (≤ 150 code lines; the chain's `__layer__`
banner like its siblings), re-exported from `tests/_downstream/conftest_plugin.py` the way
`pytest_runtest_teardown_plugin_delivery` is, so pluggy finds both hooks on the ROOT plugin:

```python
BODY_PATCH_KNOB = "HERMES_TEST_BODY_PATCH_UNDO"      # "off" (default until A.5) | "on"
BODY_PATCH_MARK = "body_patch_undo"                  # pytest.mark.body_patch_undo("on"|"off"), wins over the env

@dataclass
class CallRecord:
    base_attr: int; base_item: int; cwd_free: bool; syspath_free: bool
    late_attr: list[tuple[int, int]] = field(default_factory=list)
    late_item: list[tuple[int, int]] = field(default_factory=list)
    late_cwd: bool = False; late_syspath: bool = False

@pytest.hookimpl(wrapper=True)
def pytest_fixture_setup(fixturedef, request):
    record = getattr(request.node, "_hermes_call", None)
    mp = record and request.node.funcargs.get("monkeypatch")
    if mp is None:
        return (yield)
    a0, i0, cwd0, sp0 = len(mp._setattr), len(mp._setitem), mp._cwd, mp._savesyspath
    try:
        return (yield)
    finally:
        record.late_attr.append((a0, len(mp._setattr))); record.late_item.append((i0, len(mp._setitem)))
        record.late_cwd |= cwd0 is None and mp._cwd is not None
        record.late_syspath |= sp0 is None and mp._savesyspath is not None

@pytest.hookimpl(wrapper=True)
def pytest_pyfunc_call(pyfuncitem):
    mp = pyfuncitem.funcargs.get("monkeypatch")          # every test has one: the tripwire is autouse
    if mp is None:
        return (yield)
    record = CallRecord(len(mp._setattr), len(mp._setitem), mp._cwd is None, mp._savesyspath is None)
    pyfuncitem._hermes_call = record
    narrowed = _narrow_undo(pyfuncitem, mp, record)      # the SCOPED_MONKEYPATCH_UNDO split, unchanged
    try:
        return (yield)
    finally:
        del pyfuncitem._hermes_call
        if narrowed: del mp.undo
        counts = _undo_body(mp, record, enforce=_mode(pyfuncitem) == "on")
        pyfuncitem.user_properties.append(("hermes_body_patches", counts))
```

`_undo_body` — the one new behaviour, and the whole of it:

1. Body indices = `range(base, len)` minus the union of late ranges, for `_setattr` and `_setitem`
   separately. Counted always (`attrs`, `items`, `late_attrs`, `late_items`, `cwd`, `syspath`);
   acted on only when `enforce`.
2. Undo body `_setattr` entries in REVERSE stack order, with the overlap rule: if a LATER entry
   that is a late fixture's targets the same `(id(obj), name)`, do not touch the attribute — replace
   that late entry's tuple with `(obj, name, body_old)` so the fixture's eventual undo restores the
   pre-body value — and drop the body entry. Otherwise `setattr`/`delattr` exactly as
   `MonkeyPatch.undo` does (`NOTSET` → `delattr`), then drop the entry. Same for `_setitem` keyed on
   `(id(dict), key)`. A body entry re-patching its own earlier target is two body entries; reverse
   order restores correctly. An entry below base is never read.
3. `_cwd`: if `record.cwd_free` and not `record.late_cwd` and `mp._cwd is not None` → `os.chdir`
   and clear; `_savesyspath` likewise with `sys.path[:] = saved`. If a late fixture took either, it
   stays (pytest restores it at the fixture's undo).
4. No swallowing: a `setattr` that raises raises here, as pytest's own undo would have at teardown;
   the outcome is identical, only earlier. Nothing is logged to stdout.

The events line: `hermes_bundle_report.pytest_runtest_logreport` copies `hermes_body_patches` from
`report.user_properties` onto the call-phase `test` line as `"bp": [attrs, items, late]` when any
is non-zero; `run_tests_bundled_diag.py::_on_test` folds it into two new `FileDiag` columns,
`body_patches` (tests whose body left ≥ 1 entry) and `late_fixture_patches` (tests with a late
range that pushed), and a third, `teardown_errors` (count of `w == "teardown"` and `c == "error"`
lines, with up to 20 node ids), so the measurement in A.4 reads from `diagnosis.jsonl` and
`runs.jsonl` alone. The `diagnosis.jsonl` line gains the three keys; `render` lists them like the
others.

### B.1 Decision: restate the bar for hub edits, and take the two cheap cuts

**Restate.** The bar for `--affected` is the runner's own floor, printed and judged by the runner:
`floor = Σ quiet estimates / -j`; the printed line becomes
`Affected: … → N file(s), Σ S s, floor F s at -j J — hub edit` when `Σ > J × 60` (a hub edit is
DEFINED by that inequality, not by a module list), else `— under-a-minute edit`. The bar in the
docs: an under-a-minute edit's wall ≤ 60 s; a hub edit's wall ≤ 1.25 × floor + 20 s (packing and
start-up). A wall over its bar is a runner defect row; a floor over 60 s is the EDIT's width and is
told to the dev as such. `--fail-fast` already orders edited → direct importers → the rest with the
slowest last inside a wave (`AffectedSelection.ordered` sorts ascending by duration); nothing to
change there.

**Cut, cheap and certain.** (1) `pm.ensure("git")` once per test process instead of once per
spawn — a test-chain memo on `hermes_cli._subprocess_compat.selected_git_env` (upstream-owned, so
the memo lives in `tests/_downstream/`, the `plugin_load_memo.py` shape): ≈ 16.6 ms × 2,067 spawns
= 34 s off redo + turn_undo, and 20 s off `tests/tools/test_checkpoint_manager.py` (row
`FORK-CHECKPOINT-MANAGER-TIMEOUT` gets that for free). (2) Attribute session_models' 4.4 s/test
call phase before touching it: no spawn, no sleep, one callable is eating it; the diag plugin's
`--hermes-diag-wrap=<module:callable>` names it in one single-file run.

**Not cut.** persona_assignments: 0.54 s/test × 133 is the chain's per-test floor plus a snapshot
build each; the plugin LOAD (0.1 s/test) is by design fresh per test (`plugin_discovery_cache.py`:
discovery cached, load not). A lane there is the h3-plugins program's, not this row's. redo /
turn_undo spawn COUNT: upstream's store init (`_init_store`, six spawns) and the fork's per-path
restore are the subject under test; a fold of the five `git config` into `git init -c` is the
