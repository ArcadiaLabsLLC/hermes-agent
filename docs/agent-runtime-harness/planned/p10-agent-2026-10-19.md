### 1.2 Decisions (the row's NEEDS PLAN line)

1. **Verbs.** Four operations join `agent_runtime/subagents/model.py::REQUIRED_PARAMS` on both families:
   `settings` (`expected_generation`), `settings.set` (`expected_generation`, `expected_revision`, `changes`),
   `spawning` (`expected_generation`), `spawning.set` (`expected_generation`, `host_ref`, `paused`).
   `METHOD_PARAMS` (`subagents/params.py`) publishes them; eight new methods enter the manifest fixture.
2. **Defaults are profile state, served from the serve process, never from a child host.** The route's
   profile home is already resolved server-side (`subagents/operator.py::_subagent_profile_binding`; the

   defaults verbs touch no upstream file and no compute route. *Decision rule for the lane:* if the native
   route's profile home cannot be resolved server-side for an inherited profile, read the conversation's
   recorded head (`session.scope.head_home`, the operator family's fallback) — never the worker.
3. **The pause owner is the execution host process, and the reply says so.** `set_spawn_paused` is
   process-global; the Console's codec already models exactly that (`host_kind`, `host_ref`). No
   per-conversation pause is built (it would need an edit inside `delegate_task`). `host_kind: operator_runtime`
   pauses every persona turn in the serve process; the Console labels the scope. `spawning` / `spawning.set`
   are delivered to the process that owns the registry: native → the worker peer verb; isolated compute →
   the supervisor's observe (read) and classified control (set); operator → in-process.
4. **Upstream impact: additive, +3 lines, fixture delta zero.** `tui_gateway/compute_host.py`:

   `scripts/upstream_footprint.py --ledger`, re-derives the two rows, and reports the measured line; the
   landing confirms the fixture does not move. (A fork-side route that avoids even these lines does not
   exist: the compute process owns its registry and its name lists are upstream's.)
5. **Managed refusal.** A key present in the managed scope (`hermes_cli/managed_scope.py`, read through a
   new door `agent_runtime/_upstream_doors.py::delegation_managed_keys`) is `writable: false`,

6. **Stale.** `revision` = sha256 of the canonical `fields[]`; `settings.set` with a mismatched
   `expected_revision` refuses `Refusal.STALE`. `host_ref` = `subagents/references.py::references.generation`

   for compute, the serve's boot stamp for operator; a `spawning.set` whose `host_ref` does not match the

## 2. RT-R10-ENTRY-ID-GATE — the Launcher's tool-name spelling

### 2.1 What the tree holds

`tests/tooling/test_no_launcher_entry_id_literals.py` walks every tracked source file for the dotted id
(`ENTRY_ID`, `launcher.<a>.<b>`) with one `ALLOWED` entry (`LIST_METHOD`). The Launcher's tool name is
`appFunctionToolName` (`EterniaLauncher/lib/features/mission_control/data/app_functions/app_function_projections.dart`):
the id with dots turned into underscores. Hermes derives no name — `agent_runtime/launcher_app_functions.py::AppFunctionEntry.parse`
takes `name` from the wire — so the underscore spelling is a *leak of the same catalog* when hermes
writes it. One live instance: the incident comment in `tools/tool_search_downstream.py` (the
"one door for a name the session already has" block) names `launcher_generated_list`. The eleven other
`launcher_<a>_<b>` tokens in fork source are module, ContextVar and dict-key names
(`launcher_app_functions`, `launcher_client_requests`, …), which a bare `launcher_\w+` regex would flag.

### 2.2 Decision

**A vendored catalog fixture is the enumeration; the gate matches exact names plus the area shape the
fixture implies; the fixture is the launcher's export, vendored by the hermes sync sitting.**

- **Where:** `tests/fixtures/launcher_app_functions_catalog.json` — `{"source_commit": "<launcher sha>",
  "exported_at": "<date>", "entries": [{"id": "launcher.generated.create", "name": "launcher_generated_create",
  "read_only": bool, "always_loaded": bool, "reach": "localOnly|pairedDevice", "guidance_sha256": "…"}, …]}`.
  The export is the Launcher's projection, not hand-typed: a Launcher test (row below) writes
  `EterniaLauncher/docs/embedded_hermes/generated/app_function_catalog.json` from
  `HarnessCapabilityRegistry` through `appFunctionToolName` — the same function both projections use — and
  reds when the committed file is stale.
- **Who refreshes:** `scripts/vendor_launcher_catalog.py <path-to-launcher-export>` copies the export in,
  stamps `source_commit` from `git -C <launcher> rev-parse HEAD`, and prints the entry delta. It runs at the
  weekly sync sitting and whenever the launcher's catalog row says an entry changed (`ONE_ACTION_LAYER` S17
  already names "catalog fixture refresh if any entry shape changed").
- **How drift reds:** two directions. (a) Hermes side, positive: `tests/agent_runtime/test_launcher_catalog_fixture_parses.py`
  — every fixture entry passes `AppFunctionEntry.parse` (shape drift in the Launcher's wire reds here on
  refresh, before a live turn finds it), and every `name` equals `id.replace(".", "_")` (the derivation
  rule, pinned so a Launcher rename of the rule is caught at refresh). (b) Launcher side: the export test
  reds when the registry and the committed export differ; the sync sitting vendors it. There is no way for
  hermes alone to see a rename the launcher made after the last refresh — the fixture carries
  `source_commit` so a report can say how old it is; this is the honest limit, stated in the gate docstring.
- **The name rule (typed, not a wider regex).** The gate flags a token `launcher_[a-z0-9]+(?:_[a-z0-9]+)+`
  in the population when EITHER it equals a fixture `name` (exact), OR its second segment is an *area* the
  fixture lists (`{id.split(".")[1] for id in entries}`: `generated`, `library`, `navigation`, `agent_chat`,
  `settings`, `media`, …) and a third segment follows — so a verb added inside a known area is caught before
  the next refresh, while `launcher_app_functions` (module; no third segment) and `launcher_client_requests`
  (`client` is not an area) are not. An `ALLOWED` map with reasons, as the dotted gate has, handles any
  future collision; the lane must not grow it for the one live leak.
- **The live leak** is rewritten, not allowed: the comment names "the generated-content list tool" and the
  turn id; prose can carry the fact without the spelling (over-approximation rule: comments count).

## 3. RT-VERIFY-IMPROVE-FIRST-RESPONSE — the A/B eval, prompt set, pass bar, live run, token cost

### 3.1 What the tree holds

All five generated tools are declared `alwaysLoaded` by the Launcher
(`EterniaLauncher/lib/core/services/hermes/runtime/data/capabilities/harness_generated_capabilities.dart`),
which feeds `tools/tool_search_downstream.py::never_defer_tool_names`; the host's WHEN rule renders beside
them through `agent_runtime/launcher_app_functions.py::app_function_guidance_lines` into the
`eternia-harness.tool-guidance` section (`plugins/eternia-harness/__init__.py::render_tool_guidance`).
Today the comparison trigger sits in the **list** entry's `guidance` as a 120-word paragraph; the live
miss (QA serve 7e24ded80e, 2026-10-15) is a Markdown answer with `tool_turns=0`. The wire collapses each
tool description to one line (h-prompt-brief; `tools/downstream_schema.py::brief_request_tools`), so what
the model reads of the create entry's long description is measurable, not assumed: the model-input
receipt (`agent_runtime/profile_runner/model_input_observability.py`, kind
`redaction_safe_final_model_input`) carries `tool_schema.per_tool_chars` per tool and
`system_prompt_sections` per block; `agent_runtime/prompt_observability/mission_chat.py::MissionChatObservability`
writes the mission-chat row keyed `context_id = "ctx_…"`. The turn record
(`agent_runtime/mission_chat_turns/reads.py::mission_chat_turn_record`) carries the turn's elements and
settle state; tool counts are `tool_turns_total` (`agent_runtime/observability.py`) / `tool_call_count`
(`agent_runtime/progress.py`).

### 3.2 Decision

**The eval is a receipt reader under `evals/`, driven through the launcher_qa MCP's agent-chat send on the
owner's QA serve; arms are Launcher guidance variants, switched by QA build; the Launcher wording lands
first.** Hermes owns no wording (the proposal's rule stands). The hermes deliverable is the harness, the
prompt set, the pass bar and the cost receipt.

- **Prompt set** (`evals/genui_first_response_prompts.json`, fixed, none naming a tool). Twelve comparison
  prompts: (1) "Compare Python and Rust for a small command-line tool." (2) "Which is better for a beginner,
  Godot or Unity? Lay out the trade-offs." (3) "Rank these three laptops for video editing: MacBook Pro M4,
  Dell XPS 16, ThinkPad P1." (4) "Put PostgreSQL, MySQL and SQLite side by side for a desktop app."
  (5) "Pros and cons of React versus Flutter for our launcher." (6) "Contrast Stoicism and Epicureanism on
  their key points." (7) "Give me a comparison of the main cloud storage options for a small team."
  (8) "Electric versus hybrid for a 40 km daily commute — which wins on what?" (9) "How do the agents in
  this workspace differ in strengths and weaknesses?" (10) "Weigh up tabs versus spaces, seriously."
  (11) "Compare the last three Unreal Engine releases for shipping an indie game." (12) "SQLite WAL or
  rollback journal for us? Show the trade-offs." Three controls that must stay prose: (C1) "What time zone
  is Berlin in?" (C2) "Explain a thread versus a process in two sentences, plain text please." (C3) "Summarise
  what a Lens Episode is."
- **Hit** = the turn's first tool call is `launcher_generated_list` or `launcher_generated_create`
  (read from the turn record's elements; decision rule: if the elements do not carry tool names, the
  observability row's `tool_schema` + the child-run tool trace do, and the harness reads those) and the
  reply carries a created document id; **miss** = `tool_turns == 0` or a Markdown-only reply.
- **Pass bar**, per (agent, provider) arm: ≥ 10/12 first-tool hits (the proposal's ≥ 8/10, held at the
  same ratio), 3/3 controls prose, and the per-turn cost delta of the guidance change ≤ +80 tokens
  (chars/4) over the baseline arm. A variant that passes selection but exceeds the cost ceiling is reported,
  not adopted.
- **Arms.** A = the guidance shipped today (baseline, on the current QA build); B = the Launcher's revised
  wording: the comparison trigger stated as an instruction with an object on the **create** entry ("When the
  user asks to compare, contrast, rank or tabulate two or more things, answer with `launcher_generated_create`
  (a Composition or Table), not a Markdown table."), the list entry's paragraph cut to its first sentence;
  under 60 tokens for the pair. Arm switching = a QA build per arm (147 s); the harness records the
  launcher build stamp and the catalog's `guidance_sha256` per arm, so no override machinery is built.
- **Each prompt opens a new chat** (no cached-prefix mutation on an active conversation), on two agents
  (Amelia and Base) and every provider the QA profile has: 15 turns × agents × providers per arm.
- **Cost receipt.** Per arm, from the observability row: the `eternia-harness.tool-guidance` block chars
  and `tool_schema.per_tool_chars` for the five generated tools; the harness reports chars and chars/4
  before/after, the way h-prompt-brief reported descriptions. *Decision rule:* if arm A's receipt shows the
  create entry's wire description lost its comparison sentence to the one-line brief, the harness report
  says so first and the Launcher wording moves the trigger into `guidance` (which the brief never cuts)
  before any further variant.

  who keeps their own context and answers later."), and `DELEGATION_HANDOFF_WORK_CLAUSE` = "; submit Work

  `tools/kanban_tools.py` names) — it renders only when that tool is present, which
  `agent_runtime/personas.py::REGISTRY_HYGIENE_BLOCKED_TOOLSETS` prevents on every lane today. The
  persona-lane row that admits a Work verb flips it by admission alone.

  `(("delegate_task", "agent_chat_send"), "DELEGATION_HANDOFF_GUIDANCE")`. The Work clause is a second row

  new line). The lines stay inside the `tool_describe`-gated list, as the other fixed lines are.
- **Cost, measured the h-prompt-brief way:** the model-input receipt's `system_prompt_sections` block for
  `eternia-harness.tool-guidance` (`_prompt_block_receipts`) grows by exactly `len(line)` chars when both
