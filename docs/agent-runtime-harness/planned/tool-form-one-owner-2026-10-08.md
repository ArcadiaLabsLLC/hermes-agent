# Planned — one owner of a persona chat turn's tool form, lane fable-w2-tool-writers (2026-10-08)

**Status:** DESIGN 2026-10-08 (Fable, read-only against the tree at `f6a8d6324c`; no production code changed, no serve touched). **Rows:** the two `TAKEN 2026-10-08 fable-w2-tool-writers` rows in `Harness_Brain/20 — Active Initiatives/runtime-queue.md` (§ "Filed on arrival — 2026-10-06 (lane h-cache-hit)" and § "Filed on arrival — 2026-10-03 (lane h-chatperf)"). **Owner doc:** [`../05-chat-turn-lane.md`](../05-chat-turn-lane.md) §4 (tool posture), §5 (MCP admission). **Siblings:** [`warm-prep-integration-2026-10-08.md`](warm-prep-integration-2026-10-08.md) (the 41–50 ms `mcp_refresh` lap), [`prompt-surface-2026-10-05.md`](prompt-surface-2026-10-05.md) S1 (the per-persona defer this plan takes ownership of), commit `637b086e2c` (lane h-cache-hit: the `pre_llm_call` settle).

**One sentence.** A warm persona-chat turn's `tools[]` is written by three writers in sequence — upstream's between-turns MCP refresh (re-derives the profile-wide form through `get_tool_definitions`, re-appends the persona's deferred tools eager, keeps the BUILT bridge, and re-pins that 30-tool form to the session row every turn), the fork's re-assembly (`reapply_chat_lane_defer`, a second `get_tool_definitions` + `assemble_tool_defs`, undoing the first writer), and the session pin restore (a no-op reader on a warm resident turn, a stale-bytes writer on a rebuilt actor that the re-assembly then overwrites) — and the plan replaces all three with one fork-owned function that derives the turn's form once from a memo keyed on registry CONTENT plus this run's admitted MCP set (never `registry.generation`), publishes it only when its bytes moved, and pins exactly what the request ships; the expected warm saving is the whole `mcp_refresh` lap (41–50 ms) plus the re-assembly's share of `hooks` (≤ 19 ms), against a 259.5 ms warm median.

## 1. The owner (step 2)

**Where the turn's tools are produced once:** `agent_runtime/chat_lane_tool_form.py::settle_turn_tool_form(agent, *, session_id)` (new, fork-owned, `__layer__ = "policy"`), called from the existing `pre_llm_call` hook (`settle_turn_tools`), i.e. AFTER upstream's refresh slot and BEFORE the first request is assembled — the slot h-cache-hit already proved is the right one. The upstream refresh is switched off for persona-chat actors through upstream's own per-agent door, `agent._skip_mcp_refresh = True` (set in `_default_agent_factory`, the same attribute `agent/background_review.py` sets; no upstream line changes). The owner does the two jobs the refresh did for this lane: (a) land THIS run's admitted MCP tools into a reused actor's form — `get_tool_definitions(enabled_toolsets=agent.enabled_toolsets, …)` already yields exactly that, because `scope_toolsets_to_admission` scoped the actor's toolsets to the admission and the admitted scope is in the registry at this point; (b) the `adopt_late_connections` import-gated call, copied verbatim (an upstream public function).

**What it computes.** `form = assemble(raw_lane_defs + agent extras, persona defer names, context_length)` — the same assembly `apply_chat_lane_defer` runs today (`assemble_tool_defs` with `base.effective_defer_tools | names`, then `ensure_tool_describe_present`), so construction (W7) and every turn use ONE assembly function; `apply_chat_lane_defer` becomes `settle_turn_tool_form(agent, pin=False)` called at construction. The bridge is RE-DERIVED from the current catalog, not frozen to the built bytes (h-cache-hit's ruling: chats of one instance share one prefix whatever catalog their actor was built on; a catalog move is one break, once — OC1).

**The memo (the epoch decision).** The raw read and the assembly are memoized per process on a key that excludes per-run MCP churn:

```
key = (registry_content_revision(),        # chat_lane_bundle's (name, toolset) census minus mcp-* + check_fn_epoch — made public
       admitted_mcp_tools(agent),          # sorted (name, toolset) of the registry's mcp-* tools inside agent.enabled_toolsets — THIS run's scope, by content
       enabled, disabled, persona defer names, context_length,
       app_function_tool_scope(), config-file signature)   # the two dynamic-schema inputs upstream's key also carries
```

A warm turn with no catalog move and the same admitted set hits the memo: zero `get_tool_definitions` calls, zero `assemble_tool_defs`, one byte compare. **Chosen: caches keyed on an epoch that excludes per-run MCP churn — not epoch-neutral re-admission.** One-line reason: `teardown_mcp_admission` is the isolation guarantee that no other persona's run can observe an admitted scope (runner `_teardown_mcp_admission` docstring), so the registry must keep churning; the fork's caches are the fork's to key, and the upstream memo's generation key stops mattering once the owner no longer calls `get_tool_definitions` on a warm turn.

**Publish and pin.** If `bytes(form) == bytes(agent.tools)` the owner returns `unchanged` and writes nothing. Otherwise it publishes `agent.tools` / `valid_tool_names` on the turn's own thread exactly as `apply_chat_lane_defer` does today (no lock: with the upstream refresh off for the lane there is no concurrent writer, and `_agent_tools_lock` is upstream-private), clears `_tool_search_scope_cache`, then the block prune runs (`prune_agent_tools`, unchanged), then `persist_agent_tool_names(agent)` — **the pin stores the turn's `agent.tools` after the owner and the block prune, which is `request["tools"]` before `brief_request_tools`** (briefs and persona cache routing rewrite the request copy, never `agent.tools`). "What the wire ships" is therefore defined as the pre-brief request array; the wire-tool receipt (`persona_turn_binding.capture_final_request_tools`) measures the post-brief bytes and is the parity witness across turns and chats.

**Receipt.** One log line per settle, `tool_form_receipt turn=<id> source=<memo|rebuilt|unchanged> publishes=<0|1> pin_written=<0|1> names=<n> json_bytes=<n> admitted=<k>`; log-only (observability lands as receipts, never on the envelope). The `turn_context_receipt`'s `mcp_refresh_ms` lap stays as upstream's slot and reads ≤ 1 ms after S2.
