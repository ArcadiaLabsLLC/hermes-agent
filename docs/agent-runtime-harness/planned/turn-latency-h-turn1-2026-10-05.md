- **Tests:** `tests/agent_runtime/test_serve_rpc_agent_create.py` (new case beside the create tests); `tests/agent_runtime/test_persona_chat_actor_prewarm.py` unchanged.

### A3 — the prewarm builds the system prompt and the first turn adopts it (hermes fork + ONE additive upstream seam)

- **Goal:** `profile_conversation_system_prompt_build_ms` absent on a prewarmed chat's first turn, as it is on turn 2.
- **Cause, exactly:** `AgentRunExecution.run` (`agent_runtime/profile_runner/execute.py`) returns at `if self.request.prewarm_only:` after `acquire_agent()`, before `bind_chat_root` and the conversation. The prompt is built inside the conversation by upstream `agent/conversation_loop.py::_restore_or_build_system_prompt`: with no `conversation_history` it does not even read the session row, so on a fresh chat it always reaches `agent._cached_system_prompt = agent._build_system_prompt(system_message)` (1.1–1.6 s here, §0.2). A warm actor carries no prompt because nothing ever built one on it.
- **Change, fork half:** in the prewarm branch, after `acquire_agent()`: build the prompt with the SAME `system_message` the turn would pass (the value `bind_chat_root`/`run_conversation` receive — resolve it through the same helper, never a copy) and store it as `agent._prewarmed_system_prompt = (prompt, signature)` where `signature` is the `persona_chat_runtime_signature` the actor was warmed under. `_finish_resident_persona_chat_agent` leaves it in place. Write the timing as `profile_timing["prewarm_system_prompt_build_ms"]` on the prewarm's own receipt line.
- **Change, upstream seam (ADDITIVE, `agent/conversation_loop.py::_restore_or_build_system_prompt`):** immediately before the final "first turn of a new session" build, one guarded block: if `not conversation_history` and `getattr(agent, "_prewarmed_system_prompt", None)` is set and `_stored_prompt_matches_runtime(agent, prompt)` → adopt it as `_cached_system_prompt`, clear the attribute, emit `_emit_conversation_timing(agent, "system_prompt_prewarmed", …)`, and fall through to the existing persist/switch-note tail. Anything else (attribute absent, runtime identity moved, queued skills pending for the root — the fork half clears the attribute when `build_mission_chat_turn_context` consumed a queued-skill list) rebuilds exactly as today and the fork stamps `system_prompt_prewarm_discarded=<reason>` on the turn record. Held PR row in `planned/upstream-footprint-ledger.md`; the block is one import-free `getattr` and ~8 lines.
- **OPEN RULING A3-r1 (recommended: the seam).** The alternative with no upstream edit — pre-seeding the session row's `system_prompt` at prewarm — does not work: the restore path reads the row only when `conversation_history` is non-empty, which a fresh chat's first turn never is. A fork-only variant that monkeypatches `_restore_or_build_system_prompt` is the shape ADR 0006 forbids.
- **Positive control:** (i) unit: `_restore_or_build_system_prompt` with the attribute set and a matching runtime adopts it and emits `system_prompt_prewarmed`; with a mismatched runtime it rebuilds; plant = remove the seam block → the adopt test reds. (ii) fork: `prewarm_chat_actor` leaves a non-empty `_prewarmed_system_prompt` on the resident agent keyed by the warmed signature; plant = skip the build → red. (iii) negative: a prompt stored under a different signature is never adopted.
- **Tests:** `tests/agent/test_system_prompt_restore.py` (extend, beside the restore cases), `tests/agent_runtime/test_persona_chat_actor_prewarm.py` (extend).
- **Saving:** 1.1–1.6 s on every first turn of a prewarmed chat (5 of the 6 first turns on record carry the key at 1,273–1,578 ms). Upstream-file edit: marked, additive, one block.

### A4 — the prewarm opens the provider connection once (hermes)

- **Goal:** the first turn's `client_built → tls_done` reads like a later turn's (21–56 ms), not 262–1,454 ms.
- **Cause, as far as the records go:** the OpenAI client is built at construction (`agent/agent_runtime_helpers.py` "OpenAI client created (agent_init, shared=True)") on a process-shared `httpx.HTTPTransport` with `keepalive_expiry=20.0` (`agent/process_bootstrap.py::build_keepalive_http_client`), so a chat's first turn — minutes after its prewarm — always opens a connection, and so does any turn more than 20 s after the last. The FIRST handshake in the process costs 262–1,454 ms, every later one 21–56 ms (§0.1, §0.2). What the first one pays that the later ones do not (resolver, first full handshake, certificate chain) versus what the overlapping core build charged it is **UNVERIFIED**: every first turn on record read `builds_overlapped ≥ 1`. The one live read that settles it: `tls_done − client_built` on a first turn with `builds_overlapped=0` (lane C makes those turns the norm).
- **Change:** in `prewarm_chat_actor`, after `runner.prewarm(request)` returns `warmed`, one fail-open `HEAD` (or `OPTIONS`) to the agent's `base_url` through the agent's own client transport (`agent.client._client` for the SDK client, the raw-httpx client otherwise), timeout 3 s, no body, no model call, logged as `persona_chat_actor_prewarm_connect root=… status=… elapsed_ms=…`. Nothing is kept open; the point is that the process's first resolve and first handshake happen on the prewarm thread. Skipped for `local_llama` and any provider whose profile declares `prewarm_connect: false`.
- **OPEN RULING A4-r1 (recommended: no).** Raising `keepalive_expiry` so the connection survives to the turn is an upstream file edit against a stated reason ("reaps idle connections before reverse proxies' 30–60 s timeouts"); not proposed.
- **Positive control:** test with a fake transport counting connects: after a prewarm the counter reads 1 and the first turn's connect does not pay the fake's 300 ms first-connect delay; plant = remove the pre-open → red. Live: the next prewarmed first turn's `tls_done − client_built`.
- **Tests:** `tests/agent_runtime/test_persona_chat_actor_prewarm.py` (extend with a transport double).
- **Saving:** bounded above by 0.24–1.4 s per first turn; honest expectation after lane C removes the overlap: 0.2–0.4 s. Re-estimate from the live read above before claiming more.

### C1 — hermes: the turn-section overlay frame, built at flush (`persona_chat_turn`)

- **Goal:** one frame per flushed batch that carries everything a chat turn moves for its root, built by the section's own builders, equal field-for-field to the rows a full core built at that offset would carry.
- **Touches:** `agent_runtime/stream/frames.py` (new `persona_chat_turn_frame`, beside `running_work_frame`; `batch_turn_roots` beside `batch_ends_a_chat_turn`), `agent_runtime/stream/vocabulary.py` (`FRAME_PERSONA_CHAT_TURN = "persona_chat_turn"`), `agent_runtime/persona_chat_history/summary.py` (`only_session_ids`, applied in `rows()` AFTER the sort-and-truncate, with `omitted_session_ids` filled from the whole ranking — the C0.3 rule), a new `agent_runtime/turn_section_reuse.py` shaped like `demote_core_reuse` (`remember(frame)` / `consult(root, floor=last_offset)`), `agent_runtime/stream/__init__.py` exports.

It carries `base_offset` and `watermark` exactly as `patch_batch_frame` does because the declaring subscriber CONSUMES the batch with it: a frame that advanced no watermark would leave the next patch's `base_offset` ahead of the client's held sequence, and the launcher's gap gate (`mission_read_model.dart`, `baseOffset != _sequence` → resync) would re-hydrate on the very next fold. **One root per frame; a batch naming two roots ships two frames in root order** (two turns ending inside one 200 ms settle is the `test_two_turns_ending_in_one_batch` shape).
- **How it is built:** `persona_chat_history_summary(persona_instances=<full list>, session_db, only_session_ids={root}, omitted_session_ids=om)` → `persona_chat_trace_summary(persona_instances=[inst], event_log=EventLog())` → `operator_channel_summary(persona_instances=<full list>, persona_chat_history=<the one row>, persona_chat_trace=<the one row>, intentionally_omitted_history_session_ids=om)` filtered to the root's `channel_id` (the full list in, so `display_names` and `conversation_relationships` are the core's — variant B in the measurement, +2 ms). The instance list and the session db come from the same doors the core uses (`PersonaInstanceStore(...).list_all()`, `persona_session_db_scope()`), never `ensure_for_personas` (it writes). A read that raises → `None` → the batch demotes as today (the `running_work_frame` rule: the cost of a miss is the old lag, never a wrong row).
- **Reuse across the two subscribers:** the hub and the argv lane are two `StreamSession`s in one process draining the same events; `turn_section_reuse.consult(root, floor=last_offset)` hands the second lane the first's frame when the remembered frame's offset is at or past this batch's last offset (the W3-H2 rule, same direction argument), re-stamped with THIS batch's `base_offset`/`watermark`. Logged on the `snapshot_build` family's pattern as `turn_section reason=<start|end> root=… waited_ms=… history_ms=… trace_ms=… bytes=… source=<built|reused> pid=…`.
- **Positive control:** (i) golden: for the fixture journal the frame's `persona_chat_history` and `operator_channel` equal the same root's rows in `hydrate_running_work_owner.json`'s core (the C0.3 equality, pinned the way `tests/agent_runtime/test_stream_contract_fixture.py::test_the_running_work_section_golden_is_the_owner_hydrates_section` pins the section); plant = narrow before the truncation → a root outside a 1-row bound hydrates → red. (iii) the second lane's `consult` returns the first's frame at an equal offset and `None` at a lower one.
- **Tests:** `tests/agent_runtime/test_stream_turn_section.py` (new, the shape of `test_stream_running_work_on_turn_end.py`), `tests/agent_runtime/test_persona_chat_history_summary.py` (extend, the bound), `tests/agent_runtime/test_stream_contract_fixture.py` (new golden `persona_chat_turn.json` in the generator and the manifest).

### C2 — hermes: the batch rule, the token, and the per-subscriber skip of the demote

- **Goal:** a batch made only of one turn's events ships `persona_chat_turn` to a subscriber that declared the token and the demote core to one that did not; no `snapshot_build reason=demote` is led by a turn at a declaring launcher.
- **The batch rule (`agent_runtime/patch_coverage.py`, `batch_turn_roots(events) -> frozenset[root] | None`):** a batch is a TURN batch iff every event is one of `persona_chat.turn_started`, `persona_chat.turn_ended`, `persona_chat.projected`, `run.progress`, `run.tool.started`, `run.tool.finished`, and every event carries a non-empty `session_id` (the `run.*` lane) or `payload.root_chat_session_id` (the three `persona_chat.*`). The result is the set of those roots. Anything else in the batch — `state.patched` of any entity, `gateway.peer.updated`, `state.reconciled`, `persona_instance.chat_opened`, a `run.*` with no session (a task-run trace) — returns `None` and the batch takes today's lanes unchanged: a batch that carries patch rows goes through the existing promote/split/demote gate first. Token: `PERSONA_CHAT_TURN_CAPABILITY = "persona_chat_turn"`, a capability string beside the three existing ones (the events are not `COVERED_DOMAIN_EVENT_TYPES` and must not be: that set means "rides beside a `state.patched`", and `test_every_covered_domain_event_is_registered_or_declared_historical` gates it).
- **The gate (`agent_runtime/stream/build.py::_batch_frames_with_liveness`),** one new branch between the patch gate and the full-core fallthrough, reachable only when `delta_patches and not resync and not batch_carries_patch_rows(batch)`: `roots = batch_turn_roots(...)`; if `roots` and the token is in `accepted` → yield the overlay frame(s), return (no core, no job, no liveness: nothing to be live during); elif the token is in `promote` → `fold_variants_frame(patch=<overlay>, core=<demote core>, required_tokens={token})` per core frame, exactly the existing split (the hub's `resolve_fold_variant` returns whatever dict sits in `patch`, so the hub does not change); else fall through. A two-root batch in the split lane ships one envelope per frame with the same core. `running_work_frame` keeps shipping for END batches for the non-declaring half (unchanged; the declaring half supersedes it with the overlay's own section).
- **What still demotes, stated:** a turn whose batch is joined by anything outside the set (the cold Neko turns' `gateway.peer.updated`; a `state.patched` from a concurrent gesture; the `state.reconciled` watchdog), a resync, a room where nobody declared, and `delta_patches` off.
- **Positive control:** (i) `batch_turn_roots` over the six real windows of C0.1 replayed from a fixture: four → `{root}`, the two Neko cold turns → `None`; plant = drop `gateway.peer.updated` from the refusal → red. (iii) the hub test `test_the_hub_hands_each_subscriber_its_own_half`'s shape with one declaring and one silent subscriber: the first sink sees the overlay, the second the core.
- **Tests:** `tests/agent_runtime/test_stream_patch.py` (the token and the rule), `tests/agent_runtime/test_stream_turn_section.py` (the goldens), `tests/agent_runtime/test_serve_stream_hub.py` (the split), `tests/agent_runtime/test_serve_gateway_chat_reply_lanes.py::test_a_running_turn_publishes_its_own_start_and_end_on_the_stream_lane` (unchanged wire for a non-declaring client — it must pass untouched).
- **OPEN RULING C2-r3 (recommended: not in this lane).** `gateway.peer.updated` could join the set — no snapshot section reads the peer store — but it would make the rule "events that move nothing in the core", a different claim needing a section census; A1 removes the probe that emits it on a warm chat anyway.
