## 2. Target shape

Three things, in the order they constrain each other.

**(a) One capability authority — "what this persona MAY do".** Steps 1–5 stay where they are (they are one chokepoint already) and gain the typed account they lack: `ToolsetDeclaration` carries `issues` (a `DeclarationIssue` with a `kind` Enum: `config_read_failed`, `persona_list_ignored`, `unknown_toolset`) and `unknown` (declared names neither `toolsets.TOOLSETS` nor the registry knows); a new source value `profile_config_unreadable` replaces the lie in 1a; a fork-owned census (`agent_runtime/toolset_census.py`) answers "registered toolsets no profile declares". The legacy persona list is deleted from the model, refused at config load, stripped from store rows by one migration. Nothing in this layer knows about cost.

**(b) One cost layer that may only DEFER or DROP, with a typed reason — "which schemas RIDE this turn".** A fork-owned `agent_runtime/tool_surface.py` with one function, `compute_tool_surface(...)`, that runs the real chain exactly as the agent factory does today (`get_tool_definitions(skip_tool_search_assembly=True)` for availability, `assemble_tool_defs` with the persona config for deferral, the block) and returns a `ToolSurface` of per-name `ToolDisposition(state, reason, restorable_via)` where `state ∈ {eager, deferred, unavailable, blocked}` and `reason` is one Enum (`DispositionReason`): `persona_defer`, `curated_default_defer`, `mcp_defer`, `non_core_rule_defer`, `promoted_eager`, `check_fn_unavailable`, `backend_swap`, `registry_hygiene`, `persona_safety_policy`, `permission_mode`, `chat_lane_cost_toolset`, `chat_lane_cost_tool`, `admission_not_admitted`, `tool_search_off`. Its invariant, pinned by a test: **the cost layer never adds a name** — `eager ∪ deferred ⊆ callable(capability) ∪ bridge`. The reason is derived by ASKING upstream's classifier with controlled arguments (`is_deferrable_tool_name(name, defer_tools=frozenset(), config=…)` answers the rule half; the persona and curated sets answer the list half), never by re-spelling its ladder — a re-spelled ladder is a recorded parallel the footprint ledger would have to carry. `apply_chat_lane_defer` becomes the factory's one call into this function; its silent fallbacks become `ToolSurface.degraded` rows (the shape `ChatLaneBundle.degraded` already uses: `<component>:<ExceptionClass>`).

**(c) One receipt, three readers.** `ToolSurface.receipt()` is a dict (schema v1) with `resolution_id` (the preview's existing `_tool_resolution_id` material plus the eager/deferred lists), `eager`, `deferred`, `unavailable`, `blocked`, each name → `{reason, restorable_via?}`, `counts`, `degraded`, and the declaration's `issues` and `unknown` and the census. It is produced ONCE, at agent construction, and attached to the agent (`agent._hermes_tool_surface_receipt`, beside the wire receipt). Readers: `model_input_observability` copies it into `tool_schema.surface` beside `actual_model_tools`; `resolve_capability_block` adds a `deferred` bucket the HUD renders as one line ("18 tools deferred, reachable through tool_search; nothing is missing"); `persona tool-diff` builds the SAME object through the same function in preview mode and prints `eager N · deferred M · unavailable K · blocked J` with the per-name reason in `--json`. The serve boot writes the census as a log receipt line (the parity envelope gains no key — repo rule). Because the preview and the factory call one function on one input, the measured 45-vs-27 cannot recur: the test for it is the join itself.

What does NOT move: `_enabled_toolsets_for_chat`, `chat_lane_capability_drops`, `ChatLaneDrop`, the bundle, the block's three doors, upstream's classifier. No upstream file is edited in any slice; the Fork Boundary Map is respected by construction (every new module is under `agent_runtime/`, every edit is in a fork-owned file). The one place a widening could tempt a lane — recording which bridge alias the transport used — is settled fork-side in slice 4 (§5).
